# AGENTS.md

This is the **network** subproject of the ReWave mono-repo: the master and
manager (channel lifecycle, media library, scheduling, REST API for the UIs).

**Read [`README.md`](README.md) in this directory first** — it is the spec for
this project.

Facts an agent needs here:

- **Go** (1.27, ESM-free, single module `rewave/network`), managed with go
  modules. All commands run from this directory: `go generate ./...` (regen
  API code from openapi.yaml), `go build ./...`, `go vet ./...`,
  `go test ./...`, `make run` (generate + build + serve on `:8080`),
  `./bin/network migrate` / `migrate-status` (or `go run ./cmd/network …`),
  `go run ./cmd/adseeker <video> [--min-duration <seconds>]`. There is no
  separate lint/typecheck: `go vet ./...` + `go test ./...` + compiling is
  the gate. Format with `gofmt -l .` (must be empty).
- Dependencies are deliberately few: `modernc.org/sqlite` (pure-Go SQLite,
  hence `CGO_ENABLED=0` builds; no cgo anywhere), `github.com/lestrrat-go/jwx/v3`
  (JWT/JWKS), `github.com/docker/docker` (channel containers),
  `github.com/getkin/kin-openapi` (test-only), and `oapi-codegen` pinned as
  a `go tool` directive in go.mod. Think twice before adding more.
- `openapi.yaml` is the authoritative REST API contract (OpenAPI 3.1,
  API-first; `/v1/` paths, OAuth2 resource-server auth). API types and the
  server interface are generated by oapi-codegen into `internal/httpapi/gen/`
  at build time via the `//go:generate` directive in
  `internal/httpapi/generate.go`: gitignored, always regenerated — never
  edit, never commit that directory. `make build` and the Dockerfile run
  `go generate ./...` automatically; `go build` alone does NOT regenerate.
- Auth scopes are never hardcoded blindly: the per-operation map lives in
  `internal/auth/scopes.go`, and `scopes_test.go` verifies exact parity with
  `openapi.yaml` (every operation declares one `uiAuth` security requirement;
  the map must match, no extra, none missing). Changing the spec means
  updating that map.
- Auth (`internal/auth`): `AUTH_MODE=off` (dev bypass, default) or `jwks`
  (requires `AUTH_JWKS_URL`, optional `AUTH_ISSUER`/`AUTH_AUDIENCE`); jwx/v3
  verifies bearer tokens with a cached JWKS; non-API routes (healthz) are not
  authenticated.
- Architecture is pragmatic Go: packages under `internal/` (`apperr`, `config`,
  `db`, `uuid`, `auth`, `httpapi`, `channel`, `media`, `scheduling`,
  `watching`) each own their domain + store + service; no DDD onion, no
  architecture checker — `internal/` visibility is the boundary. Cross-package
  flows: `scheduling` and `watching` consume `channel` (types) and
  `scheduling → media` (via a `VideoSource` interface); nothing imports
  `httpapi` except `cmd/network`. Handlers live in `httpapi/server.go` and
  delegate to services; DTO↔domain conversion in `httpapi/dto.go`,
  `httpapi/watching.go`.
- Application errors: services return `apperr.Validation/NotFound/Conflict`
  errors (400/404/409); `httpapi.WriteError` maps them to the openapi
  `Error` body shape `{code, message}`. Path/query parameter validation is
  handled by generated code and routed through the same mapper via the
  `ErrorHandlerFunc` in `cmd/network/main.go`.
- Environment: `internal/config/config.go` loads `.env` from the working
  directory (gitignored; real env wins) — all variables and defaults are
  documented in `.env.example`. Runtime knobs: `PORT`, `HOST`, `LOG_LEVEL`
  (debug|info|warn|error, slog), `DB_PATH`, `MEDIA_ROOT`, `MEDIA_HOST_PATH`,
  `DOCKER_SOCKET`, `CHANNEL_IMAGE`, `WATCH_KEEPALIVE_SECONDS`, `AUTH_MODE`,
  `AUTH_JWKS_URL`, `AUTH_ISSUER`, `AUTH_AUDIENCE`.
- Migrations are **forward-only** and live in `internal/db/migrations/`,
  **embedded** into the binary, checksum-validated (SHA-256), applied at
  startup. Applied files must never be edited/renamed/deleted, and new files
  must sort after applied ones — add a new `NNNN_description.sql` instead.
  Timestamps in SQLite are UTC `YYYY-MM-DD HH:MM:SS` (helpers in
  `internal/db/time.go`).
- SQLite specifics: the pool is capped at `MaxOpenConns(1)` (single writer,
  and **queries must not run while a result set is open** — load rows first,
  then query per row; see `media.Store.FindAll`). Multi-statement writes go
  through `db.WithTransaction`.
- Scheduling: wall-clock slot times resolve in the **server's local
  timezone** (set `TZ` in Docker). Resolution is deterministic (path-ordered,
  cycling candidates) and covers today + tomorrow; the current playlist per
  channel is kept in memory (`scheduling.playlistStore`), set on start.
  `scheduling.Service.PlaylistFor` serializes the shim format for today's
  Python channel prototype (flat `timestamp`/`file`/`type` slots via the
  `PLAYLIST` env) — a temporary measure until the channel HTTP API exists.
- Ingestion: `media.Service.Add` probes duration synchronously (ffprobe),
  inserts the video (`processed=false`) and runs ad-break detection in a
  background goroutine; failures are logged and leave the video unprocessed.
  Re-triggering means delete + re-add.
- Manual API testing without a frontend: `requests/*.http` (VS Code REST
  Client + JetBrains HTTP client; variables in `.vscode/settings.json` and
  `requests/http-client.env.json`, real tokens only in the gitignored
  `requests/http-client.private.env.json`). Keep request bodies in sync with
  the example objects in `openapi.yaml`.
- The network is the only component allowed to know channels: control flow
  is strictly network → channel, never the reverse. The SQLite media library
  is single-writer and owned by the network; it is never mounted into other
  containers.
- Never run docker-build/container smoke tests from inside the devcontainer
  (docker-in-docker is unreliable there); the runtime is covered by the fake
  runtime in tests. Verify channel behavior on the host instead.
- Repo-wide facts and gotchas live in the root `AGENTS.md`.
